1. ENABLE_MOCK_OCR esta documentada pero el codigo no la lee
--------------------------------------------------------------------------------

La agregaste al .env.example y a la guia de despliegue:

    ENABLE_MOCK_OCR=false   # Si es false, no alucina compras ante fallos

Pero la busque en todo backend/src y no aparece en ninguna parte. La variable no
hace nada.

Lo que decide de verdad si el simulador participa es esto, en
ocr-dispatcher.service.ts:

    const hasApiKey = Boolean(process.env.GEMINI_API_KEY);
    const isProduction = process.env.NODE_ENV === 'production';
    if ((hasApiKey || isProduction) && !input.simulateFailure) { ... }

O sea depende de si hay API key o si estamos en produccion, no de la variable.

Dos consecuencias:

  - Si alguien pone ENABLE_MOCK_OCR=false esperando cerrar el simulador, no pasa
    nada. Y si lo pone en true esperando usarlo para probar, tampoco.
  - En desarrollo sin GEMINI_API_KEY el simulador sigue inventando facturas
    completas. Es el caso menos grave porque sin key igual no hay OCR, pero la
    pantalla muestra la factura inventada como si fuera real.

Se arregla con una linea, leyendo la variable en esa condicion. O si preferis que
el gate sea la API key, saca la variable de los documentos para que no prometan
algo que no existe.

Aparte, el 422 lo detecta comparando el texto del mensaje:

    const statusCode = errorMsg.includes('No fue posible digitalizar') ? 422 : 500;

Funciona, pero si alguien cambia ese texto el status se cae a 500 sin que nadie
se entere. Un codigo de error en el objeto seria mas firme.
